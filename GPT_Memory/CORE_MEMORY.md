# YSOS Core Memory（核心記憶）

- **版本：** v1.0
- **狀態：** Portable reference（可移植參考資料）；不是 Runtime 執行證明。
- **用途：** 為不同 AI 助手提供最小必要的 YSOS 概念、術語與協作脈絡。

## 1. YSOS 的定位

YSOS 是一套人機協作與認知治理架構，使用矩陣、模式、路由規則、證據檢查及人類授權邊界，降低理解漂移、確認偏誤、無根據推論與未授權施工的風險。

文件中描述的流程或模組，不代表目前任何 AI 產品已自動載入或執行它們。每次宣稱執行狀態，都必須提供可查證證據。

## 2. 核心治理元件

| 名稱 | 中文語意 | 核心責任 |
|---|---|---|
| M9 | 真假／證據驗證矩陣 | 檢查主張是否有證據支持，區分事實與未驗證內容 |
| M10 | 理解正確性驗證矩陣 | 檢查是否正確理解需求、來源、上下文與限制 |
| AHG | Anti-Hallucination Gate／防幻覺閘門 | 統合防幻覺檢查；未執行時不得宣稱通過 |
| M46 | Devil Advocate Matrix／反對者矩陣、確認偏誤防火牆 | 挑戰假設、尋找反例、辨識盲點；可掛載 Grill-Me Mode |
| M47 | Scope Lock Matrix／範圍鎖定矩陣 | 鎖定目標、非目標、允許修改範圍、禁止事項與驗收條件 |

以上定義是本記憶包提供的參考語意；如權威版本另有明確定義，應記錄版本差異並交由人類決策者仲裁。

## 3. Grill-Me Mode 的位置

Grill-Me Mode（反詰澄清模式／需求壓力測試模式）掛載於既有 M46，不另創矩陣。其目的在於先釐清目標、假設、範圍、依賴、風險與驗收標準，再決定是否進入規劃或施工。

詳細規格請讀取 [GRILL_ME_MODE_M46_SPEC.md](GRILL_ME_MODE_M46_SPEC.md)。

## 4. 協作角色的通用原則

- **人類決策者：** 決定目標、範圍、優先級、治理衝突與高影響操作授權。
- **規劃／審核型 AI：** 拆解需求、制定驗收條件、檢查差異、風險、測試證據及文件一致性。
- **施工代理／程式工具：** 僅執行明確核准的任務與範圍，回報變更檔案、命令、測試、結果與限制。
- **版本庫：** 保存版本化規格、決策、變更差異與交接狀態。

實際工具角色應依使用者當前指定的工作流調整，不應把此處的通用角色分工當成對所有專案都固定不變的命令。

## 5. 狀態標籤

- `CONFIRMED_BY_USER`：人類已明確確認。
- `OBSERVED_EVIDENCE`：由可追溯來源直接觀測。
- `INFERENCE`：根據現有證據推導，仍可能有誤。
- `PROPOSAL`：候選方案，尚未核准。
- `UNKNOWN`：資訊不足。
- `CONFLICT`：來源或規格互相矛盾。
- `BLOCKED_ON_USER`：等待人類決策或授權。
- `APPROVED_FOR_PLAN`：可進入規劃，不代表可施工。
- `APPROVED_FOR_IMPLEMENTATION`：已明確授權按鎖定範圍施工。
- `OUT_OF_SCOPE`：本次明確不處理。
- `NOT_RUN`：未執行；不能視為通過。
- `PASS`／`FAIL`：只適用於已執行且有證據的驗收項目。
